# MiniCore 文档维护约定

本文档定义 `Docs/` 的通用维护规则。面向开发者、AI 和自动化工具；具体架构、协议与测试结论仍以各自专题文档为准。

## 历史记录顺序

带日期的优化记录、测试结论、变更归档和决策日志必须按时间倒序排列：**最新记录在最上方，较早记录向下排列**。新增记录时插入所在历史分区的顶部，不附加在末尾。

- 使用 `YYYY-MM-DD` 作为新记录标题日期。
- 同一天的多条记录按实际发生时间倒序；标题应说明事件，避免只写日期。
- 报告目录可能使用 UTC 时间戳；若与本地日期不同，正文必须明确说明，不能用目录名推断本地发生日期。
- 新记录若推翻、收窄或冻结旧结论，必须明确写出关系，不能让两条结论彼此矛盾。

## 不适用范围

以下内容按语义顺序组织，不按倒序重排：使用步骤、编号流程、系统架构分层、协议字段布局、依赖关系、故障排查步骤和 API 参考。

## 更新要求

代码、测试或设计决策发生实质变化时，在同一任务中更新对应专题文档、优化路线图和性能结论；文档之间使用相对 Markdown 链接。修改完成后检查标题层级、链接和历史分区的日期顺序。
